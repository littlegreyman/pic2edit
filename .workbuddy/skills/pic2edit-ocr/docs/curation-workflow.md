# 知识库采编管理操作手册（无幻觉入库）

目标：把协会收集的法律法规、案例、章程、通知等**快速、无幻觉、可溯源**地进入检索知识库。
核心铁律：**AI 只抽取/切分/打标，绝不重写正文**；人机协同终审；入库前强校验。

---

## 一、无幻觉入库五条铁律

1. **正文永远来自原文**：入库的正文片段 = 原始文件解析后的文本，AI 不得改写、概括、补全内容。
2. **AI 辅助抽取，人终审**：LLM 只抽元数据（类型/机构/生效日/标签），错误只影响检索排序，不影响事实；高敏感内容人工必审。
3. **切片绑定溯源**：每个向量切片关联 `doc_id + 条款号 + 原文快照`，回答只能引用，不能创造。
4. **入库自动校验**：切片文本与原文段落做一致性比对，不一致**拒入**并告警。
5. **回答强制引用 + 无依据拒答**：检索不到或置信度低时直接拒答，不编造。

## 二、角色与分工

| 角色 | 职责 |
|---|---|
| 采编员 | 收集来源、初清洗、上传解析、初步打标 |
| 审核员 | 终审抽取字段与切分、确认版本/时效关联 |
| 管理员 | 流程配置、权限、定期复核、审计 |

---

## 三、采编流程（8 步）

```
① 收集  → ② 初审(去重) → ③ 解析(保结构) → ④ 抽取+切分(AI辅助)
   → ⑤ 人工审核 → ⑥ 版本关联 → ⑦ 入库(绑定溯源) → ⑧ 校验+复核
```

1. **收集**：官网/邮箱/纸质扫描/会员报送 → 统一收件箱（按来源建目录）。
2. **初审**：合法性、去重（按 `doc_number` 或标题哈希），剔除无关/重复。
3. **解析**：用 **RAGFlow / MinerU** 解析 PDF/扫描件/带表格法规，输出保留条款层级的文本（避免 OCR 丢字错字）。
4. **抽取 + 切分（AI 辅助，仅元数据）**：LLM 抽 `doc_type / issuing_authority / effective_date / expiry_date / tags`；正文**按条款**切分，保留层级编号。
5. **人工审核**：对照原文核对抽取字段与切分边界；高敏感（处罚/内部通报）必审，普通抽检 ≥ 20%。
6. **版本关联**：建立 `supersedes / superseded_by`，旧规置 `SUPERSEDED`。
7. **入库**：写 PostgreSQL（元数据 + BM25）+ Qdrant（向量，BGE-M3），每个切片绑定溯源。
8. **校验 + 复核**：自动比对切片↔原文一致率；定时扫描临期文档提醒复核。

---

## 四、防幻觉的技术落地点

- **解析保结构**：RAGFlow 对表格/多栏法规优于通用切分，从源头减少错字丢段。
- **抽取 prompt 约束**：「只输出 JSON 字段，严禁改写或补全正文内容」。
- **入库校验脚本**：对每段切片计算与原文段落的文本相似度 / simhash，低于阈值（如 0.98）即拒入并告警。
- **问答层约束**：RAG 只取 top-k 切片原文拼进 prompt，要求「仅依据所给片段作答，并标注 doc_number + 条款号」。

## 五、快速入库工具链（阶段1 在 Mac 可跑）

| 环节 | 工具 | 说明 |
|---|---|---|
| 解析 | **RAGFlow**（Docker arm64）/ MinerU | 保结构解析，输出 Markdown/JSON |
| 抽取 | Ollama `qwen2.5:32b` 或 7B | 抽元数据 JSON，约束不写正文 |
| 审核 | Dify 数据集管理 / 轻量标注页 | 人工核对与必审 |
| 入库 | Python 脚本（qdrant-client + SQLAlchemy） | 批量写向量+元数据，绑定溯源 |
| 校验 | 入库脚本内联相似度比对 | 切片↔原文一致性 |

**简化 ingest 脚本思路（伪代码）**
```python
doc = ragflow.parse(file)                 # 保结构解析
meta = ollama.extract_meta(doc.text)      # 仅抽 JSON 字段
chunks = split_by_clause(doc.text)        # 按条款切分
for c in chunks:
    assert similarity(c.text, original[c.span]) > 0.98   # 无幻觉校验
    qdrant.upsert(vector=bge_m3(c.text), payload={**meta, "clause": c.no, "src": c.text})
pg.insert(meta)                           # 元数据+BM25
```

## 六、质量门禁（验收标准）

- 抽取字段准确率 ≥ 95%（抽检）
- 切片↔原文一致率 **100%**
- 无依据问题拒答率 **100%**
- 时效/版本标注准确率 **100%**

---

## 七、POC 落地步骤（Mac 上先跑通）

1. 用 RAGFlow（Docker）解析 10–20 篇样本，确认结构保留良好。
2. 跑抽取+切分+入库脚本，人工抽检字段与切片。
3. 在 Dify 接 Ollama，用 `docs/eval-set.md` 验问答是否带正确出处、无依据是否拒答。
4. 建立采编台账（Excel/Notion）：来源、责任人、状态、审核记录。
5. 小批量（50–100 篇）试跑，稳定后再扩规模。
